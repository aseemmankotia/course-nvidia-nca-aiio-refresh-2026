## Chapter 4: AI Cluster Networking and Storage Infrastructure — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | InfiniBand NDR bandwidth and typical latency? | 400 Gb/s (50 GB/s) bidirectional per port. Typical latency <700ns switch-to-switch. Exam tip: NDR = 2x HDR bandwidth. Tests on bandwidth/latency trade-offs vs Ethernet. |
| 2 | RoCEv2 over 400GbE typical latency versus InfiniBand NDR? | RoCEv2: 2-5μs. InfiniBand NDR: <1μs (700ns typical). Difference due to Ethernet PFC pauses and switching overhead. Exam tip: RoCEv2 3-5x higher latency but acceptable for most AI workloads. |
| 3 | What does GPUDirect RDMA eliminate in GPU-to-GPU communication? | Eliminates: CPU involvement, system memory copy, kernel context switches. Enables: zero-copy GPU memory to GPU memory via RDMA. Reduces latency from 20-30μs to 2-5μs. Exam tip: GPUDirect RDMA requires RDMA-capable network (IB or RoCE). |
| 4 | BlueField-3 DPU primary offload functions for AI clusters? | Offloads: RDMA transport (RoCE, IB), NVMe-oF storage protocol, overlay networking (VxLAN), IPsec encryption. Result: 30-40% CPU reduction. Exam tip: DPU frees CPU/GPU for compute, not for doing ML operations. |
| 5 | Lustre stripe count parameter - what does it control? | Number of OSTs (Object Storage Targets) a file is distributed across. Default: 1 (single OST). Recommended for checkpoints: 4-8. Command: 'lfs setstripe -c 8 /path'. Exam tip: Low stripe count = common bottleneck in parallel file systems. |
| 6 | When to use InfiniBand vs RoCEv2 for AI training cluster? | InfiniBand: <1μs latency needed, >128 GPUs, pure RDMA workload, budget available. RoCEv2: 2-5μs acceptable, mixed workloads (management + training), existing Ethernet infrastructure, cost-sensitive. Exam tip: RoCEv2 sufficient for most LLM training. |
| 7 | Minimum checkpoint write bandwidth formula for X GB model in Y minutes? | Bandwidth (GB/s) = (Model size in GB) / (Time in seconds). Example: 350GB in 2 min = 350/120 = 2.92 GB/s. Exam tip: Add 20% headroom for metadata overhead. Tests on capacity planning. |
| 8 | Parallel file system (Lustre, GPFS) vs NFS for AI training - when to use each? | Parallel FS: >5 GB/s bandwidth needed, >32 nodes, frequent checkpoints, random access. NFS: <2 GB/s, <16 nodes, infrequent writes, simple datasets. Exam tip: Parallel FS scales horizontally (add OSTs), NFS doesn't. |
| 9 | SHARP (Scalable Hierarchical Aggregation and Reduction Protocol) benefit in InfiniBand? | In-network all-reduce operations performed by switches, not GPUs. Reduces all-reduce latency 5-10x. Only available in InfiniBand (not RoCEv2). Exam tip: SHARP = key advantage for frequent collective operations (all-reduce, all-gather). |
| 10 | Object storage (S3) vs parallel file system for training data - when to use S3? | S3: Initial data ingest, large datasets (>100TB), infrequent access, archive. Parallel FS: Active training, frequent access, low latency needed. Never use S3 for: checkpoints, epoch-boundary data loads. Exam tip: S3 GET latency 10-100ms vs <1ms for Lustre. |
| 11 | Typical IOPS requirement for checkpointing 500GB model? | Metadata IOPS: 100K-500K for file creation/updates. Data IOPS: Bandwidth-bound (large sequential writes), IOPS irrelevant. Exam tip: Checkpoints need bandwidth (GB/s) not IOPS. Metadata IOPS matters for many-file checkpoints. |
| 12 | InfiniBand adaptive routing vs static routing - impact on AI workloads? | Adaptive: Dynamically avoids congested paths, prevents hotspots, consistent latency. Static: Persistent congestion on specific links, 10-20x latency variance. Exam tip: Low utilization + high latency variance = static routing misconfiguration. |
