## Chapter 2: AI/ML/DL Fundamentals and GPU Architecture — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Training vs Inference: Which requires backpropagation? | Training only. Training: forward pass → compute loss → backpropagation → update weights. Inference: forward pass only, weights frozen. Exam tip: Inference is 10-100x faster because no gradient computation or weight updates. |
| 2 | GPU memory hierarchy from fastest to slowest? | Registers (per-thread) → Shared memory (per-block, 48-164 KB) → L1 cache → L2 cache (6-40 MB) → Global memory (16-80 GB). Exam tip: Shared memory is 100x faster than global memory - critical for optimizing matrix operations. |
| 3 | Precision formula and when it matters most? | Precision = TP/(TP+FP). High precision = few false positives. Matters when false positives are costly (spam filter marking important email as spam, fraud detector blocking legitimate transactions). Exam tip: Precision answers 'Of all positive predictions, how many were correct?' |
| 4 | Recall formula and when it matters most? | Recall = TP/(TP+FN). High recall = few false negatives. Matters when missing positives is dangerous (cancer detection, fraud detection, security threats). Exam tip: Recall answers 'Of all actual positives, how many did we catch?' |
| 5 | NVIDIA A100 GPU: CUDA cores vs Tensor Cores? | 6,912 CUDA cores (general parallel compute) + 432 Tensor Cores (specialized for matrix operations, 10-20x faster for AI). Exam tip: Tensor Cores accelerate FP16/INT8 matrix multiply-accumulate, critical for training and inference speedup. |
| 6 | Batch size in training: effect on memory and convergence? | Larger batch → more GPU memory (stores activations for all samples), faster training (more parallelism), but worse generalization. Smaller batch → less memory, slower training, better generalization. Exam tip: Memory scales linearly with batch size; typical range 16-512. |
| 7 | Learning rate: too high vs too low symptoms? | Too high: loss explodes or oscillates, training diverges. Too low: training extremely slow, gets stuck in local minima. Exam tip: Typical range 0.0001-0.01. Use learning rate decay/scheduling for best results. |
| 8 | Supervised vs Unsupervised vs Reinforcement learning: data requirements? | Supervised: labeled data (X→Y pairs). Unsupervised: unlabeled data (find patterns). Reinforcement: environment with rewards (learn by trial). Exam tip: Question will describe data type - labeled, unlabeled, or reward-based - to test which paradigm. |
| 9 | F1 Score: formula and when to use? | F1 = 2 × (Precision × Recall)/(Precision + Recall). Harmonic mean balances precision and recall. Use when both false positives and false negatives matter equally. Exam tip: F1 heavily penalizes if either metric is low (not simple average). |
| 10 | Why GPU accelerates matrix multiplication vs CPU? | GPUs have thousands of cores (vs 8-64 CPU cores) executing matrix operations in parallel. Matrix multiply of M×N and N×P requires M×N×P operations - massive parallelism. Exam tip: GPU advantage is parallelism (not clock speed). CPUs run 3-4 GHz, GPUs 1-2 GHz. |
| 11 | Epoch vs Iteration vs Batch in training? | Epoch = one complete pass through entire dataset. Batch = subset of data processed together (e.g., 256 samples). Iteration = one weight update (one batch). Exam tip: If 10,000 samples, batch size 100 → 100 iterations per epoch. |
| 12 | INT8 vs FP16 vs FP32 inference: speed and accuracy trade-off? | INT8: 4x faster than FP32, 1-2% accuracy loss. FP16: 2x faster than FP32, <0.5% accuracy loss. FP32: baseline. Exam tip: Inference typically uses INT8 or FP16. Training uses FP16/FP32 mixed precision. Question tests when precision trade-off is acceptable. |
