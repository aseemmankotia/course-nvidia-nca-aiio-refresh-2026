## Chapter 7: GPU Monitoring, Troubleshooting, and Optimization — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | nvidia-smi command to query GPU utilization, memory free, and temperature in CSV format every 5 seconds? | nvidia-smi --query-gpu=utilization.gpu,memory.free,temperature.gpu --format=csv --loop=5 Exam tip: --loop=N is interval in seconds. Metric names must be exact: utilization.gpu (not gpu.utilization), memory.free (not free.memory). --format=csv,noheader,nounits for clean parsing. |
| 2 | DCGM architecture: what are the 4 main components? | 1. Host Engine (nv-hostengine) - central daemon 2. Agents - lightweight processes on each node 3. Groups - logical GPU collections 4. Policies - health checks and alerts Exam tip: DCGM runs agents on each node that report to central host engine. Groups let you monitor GPU subsets. Policies define when to alert. |
| 3 | At what temperature does thermal throttling typically start on NVIDIA datacenter GPUs? | 80-85°C - GPU reduces clock speeds to prevent damage. Exam tip: Normal operating temp is 60-75°C. Above 80°C = throttling starts. Above 90°C = critical, may shut down. If you see high temp (>80°C) with low utilization, suspect thermal throttling. |
| 4 | CUDA 12.4 minimum driver version requirement? | 530.30.02 or higher Exam tip: Driver version must be >= minimum for CUDA version. CUDA 12.x requires 525+ drivers, but specific versions (12.4) need 530+. Check compatibility matrix. Common mistake: updating CUDA without updating driver. |
| 5 | When should you use Nsight Systems vs Nsight Compute for GPU profiling? | Nsight Systems: System-wide timeline, CPU+GPU interaction, data pipeline bottlenecks, multi-GPU coordination Nsight Compute: Individual CUDA kernel optimization, memory bandwidth, warp efficiency, register usage Exam tip: Systems = big picture/timeline. Compute = kernel details. Use Systems first to find slow kernels, then Compute to optimize them. |
| 6 | What does nvidia-smi showing GPU but training code saying 'no CUDA-capable device' indicate? | Driver vs CUDA version mismatch. nvidia-smi uses driver API (works), but CUDA runtime requires compatible driver version. Exam tip: nvidia-smi working ≠ CUDA working. Check driver version >= CUDA minimum requirement. Most common after toolkit upgrades without driver upgrade. |
| 7 | How much GPU memory does mixed precision (FP16) save compared to FP32? | ~50% memory reduction for activations and gradients (16-bit vs 32-bit). Model weights stay FP32 for numerical stability. Exam tip: FP16 training allows ~2x batch size increase. Use automatic mixed precision (AMP) with loss scaling to prevent underflow. PyTorch: torch.cuda.amp, TensorFlow: mixed_precision policy. |
| 8 | DCGM command to start profiling metrics for GPU group with ID 5? | dcgmi profile --start --group 5 Exam tip: DCGM uses groups to organize GPUs. Common workflow: create group (dcgmi group -c), add GPUs, then profile/monitor group. Stop with --stop flag. View with dcgmi profile --list. |
| 9 | GPU shows 45% utilization and 30% memory usage, but training is slow. What's the likely bottleneck? | Data pipeline bottleneck - GPU waiting for CPU preprocessing. Exam tip: Low GPU util + low memory = GPU idle waiting for data. Solutions: increase num_workers in dataloader, prefetch to GPU, optimize CPU preprocessing, use GPU-accelerated preprocessing (DALI), cache preprocessed data. |
| 10 | Common solutions for 'CUDA out of memory' error? (List 4) | 1. Reduce batch size 2. Enable gradient checkpointing 3. Use mixed precision (FP16) 4. Clear cache: torch.cuda.empty_cache() Exam tip: Try in order: reduce batch size first (easiest), then gradient checkpointing (40-60% memory savings), then mixed precision (2x batch increase). Clearing cache helps fragmentation but doesn't increase capacity. |
| 11 | nvidia-smi metric names: what are the exact strings for GPU utilization percentage and memory used in MB? | utilization.gpu (percentage) memory.used (MB) Exam tip: Exact names matter for --query-gpu. Common wrong answers: gpu.utilization, gpu_util, memory_used. Also available: memory.free, memory.total, utilization.memory (memory controller util, different from usage). |
| 12 | What does gradient accumulation do and when should you use it? | Accumulates gradients over N forward passes before updating weights. Simulates larger batch size without increasing memory. Exam tip: Use when you want effective batch 256 but can only fit batch 64 in memory (accumulate 4 steps). Doesn't reduce memory per batch - still OOM at same batch size. Different from gradient checkpointing (which saves memory). |
